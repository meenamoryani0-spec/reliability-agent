# Design System: Reliability Operator Workspace

This document applies the installed StitchDesign plugin's semantic design workflow
to the existing application. The installed plugin is skills-only; no Stitch
generation MCP was available. Online Stitch access was blocked by browser policy.
The implementation is local, guided by this document, not generated by Google Stitch.

## 1. Visual Theme & Atmosphere

A restrained operations desk: graphite surfaces, clear evidence, a muted moss
accent, and comfortable spacing. Daily-app density 5/10, asymmetric composition
6/10, restrained motion 2/10. The product is a web application at `/dashboard`;
`/` introduces that application with explicitly illustrative evidence.

The overview prioritizes recorded signals, incidents, and bounded investigation.
An asymmetric main-column/investigation-column layout differentiates operational
evidence from the next action. On compact screens the investigation panel moves
before the longer observation lists so the primary interaction remains accessible.

## 2. Color Palette & Roles

- **Graphite Canvas** (#14171A) — application background.
- **Navigation Graphite** (#101315) — sidebar and navigation depth.
- **Evidence Surface** (#1B2024) — recorded evidence and summary surfaces.
- **Raised Slate** (#22272C) — controls and subordinate groups.
- **Structural Slate** (#30363D) — borders and separators.
- **Paper Ink** (#EDF0F2) — primary text on dark surfaces.
- **Quiet Steel** (#A0AAB4) — secondary text and metadata.
- **Muted Moss** (#B6D79D) — the single interaction accent, primary actions,
  selected navigation, and focus rings.
- **Evidence Amber** (#E0C592) and **Failure Rose** (#EDB9B4) — semantic warning
  and failure indicators only; always accompanied by explicit text.

The public homepage uses #111518 for its canvas and #1B2227 for its surfaces.
Do not introduce neon, purple gradients, pure black, or glowing buttons.

## 3. Typography Rules

Use the bundled Geist Sans and Geist Mono assets. No external font requests.
Headlines use medium weight and tight tracking; operational headings are 29–32px,
panel titles 16–26px, and the homepage headline scales with `clamp()`.
Primary prose and form input text are 14–16px with relaxed leading. Compact
metadata is subordinate at 12–13px; tiny labels never carry the only explanation.
Monospace distinguishes timestamps, counts, execution references, and JSON.
Sans-serif only in the application. Preserve wrapping for IDs and narrow screens.

## 4. Component Stylings

- **Actions:** moss fill for the primary investigation action; slate outline for
  refresh and secondary operations. Controls have at least 44px targets, visible
  focus, disabled states, and restrained press feedback.
- **Evidence groups:** 7–10px corners, thin structural borders, no decorative
  elevation. Service and incident lists use dividers rather than repeated cards.
- **System map:** three real category summaries derived from the latest loaded
  observations. Each available category opens filtered checks. Empty or unavailable
  categories are disabled. Recorded failures, stale records, and uncertainty are
  distinct. These are data controls, not a three-card marketing feature row.
- **Investigation:** visible actual mode, labeled textarea, explicit synthetic/live
  disclosure, inline errors, a bounded pending state, and cited results. Never
  imply a fixture is a live model response.
- **Evidence drawer:** a readable right-side detail surface, native modal focus
  containment, Escape dismissal, explicit close action, and sanitized disclosures.
- **States:** layout-shaped loading skeletons, honest empty states, retained stale
  data on refresh failure, partial-history warnings, and offline/disabled policies.
- **Login:** the same graphite/moss palette with readable labels and helper text.

## 5. Layout Principles

Use CSS Grid and max-width containment. The app sidebar is 230px on large screens;
the overview has a fluid evidence column and a 320–360px investigation column.
Below 1200px it becomes one main column. Below 768px content grids collapse to one
column and navigation becomes an explicit expandable menu. Summary metrics and
small navigation controls may remain paired, rather than shrinking text.

The homepage uses a left-aligned split hero with one primary CTA and a real grid
for the illustrative workflow. Diagram labels occupy their own flow layout;
no absolute-positioned content or headline/image overlaps. Contextual icons
replace the plugin's suggested inline stock photography because operational
legibility takes precedence over decoration. No external images are required.

## 6. Motion & Interaction

Use short CSS hover/press feedback. Loading skeletons may breathe while actual
work is pending. The evidence drawer uses a short transform/opacity entrance.
Respect `prefers-reduced-motion` globally. Do not perpetually pulse recorded
health, counts, or fixtures: motion must not imply a live connection or polling.
No automatic carousel, typing simulation, fabricated chart, or background polling.
The four homepage stages change an explicitly illustrative explanation.

## 7. Anti-Patterns (Banned)

- No invented uptime, impact, customer counts, root causes, or recovery claims.
- No synthetic/live identity merging; refresh reads stored records only.
- No browser approval, retry, or remediation write controls.
- No decorative activity dots presented as proof of enabled/live behavior.
- No tiny horizontal mobile navigation or horizontal document overflow.
- No generic feature-card trio, emoji branding, neon glows, or gradient headlines.
- No copied placeholder brands, stock avatars, external image dependencies,
  custom cursors, filler scroll instructions, or unsupported marketing claims.
- No weakening signed sessions, fixed backend origins, schema limits, source
  provenance, stale evidence, or scoped historical recovery semantics.
